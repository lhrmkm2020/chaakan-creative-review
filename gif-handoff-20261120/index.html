착한구두 META · 착구 GIF 인수인계

11/20 금요일 · 착한구두 META 1계정 · 광고주가 추가 GIF 세팅을 요청한 경우

파일 받으면 먼저 확인

  1. 광고협업 스레드에서 파일·상품·라이브 요청을 확인합니다. 지난 11/19 등록분에 착구 GIF가 이미 있어, MKM 세팅 이력과 Meta에서 원본 파일명·영상 내용·목적지 세트를 대조합니다. 동일 파일은 재등록을 건너뛰고, 수정본은 교체인지 추가인지 확인합니다.
  2. 새로 받은 파일을 품목별로 묶고 아래 위치에 세팅합니다. 착구 GIF는 받은 세로 원본 그대로 영상 소재로 등록합니다. 광고명은 원본 파일명을 유지하고, 일반 이미지용 자동 음악은 GIF에 적용하지 않습니다.
  3. 같은 SKU·혜택으로 검증된 최신 기본문구·제목·설명을 복사합니다. 영상 속 가격과 1+1/단품 구분을 랜딩과 맞춥니다. 앤드리는 포근함·스웨이드 소구를 사용합니다.

라이브 일정과 예외

  • 11/20 즉시 라이브 요청은 요청 시점 기준으로 반영하고, 목요일 11/19 19시 일정을 복사하지 않습니다.
  • 11/23 월요일 00:00 KST로 잡힌 버칸·시트롱·폴비·턴즈·스쿱은 최신 요청에 변경이 없으면 해당 시각으로 예약합니다. 시작 시간을 받은 적이 없는 추가분은 OFF로 준비하고 요청 스레드에서 확인합니다. 스쿱은 재고·구매 가능 상태까지 확인 후 라이브합니다.
  • 풀문은 재입고 후 재개된 상태입니다. 새 GIF에 라이브 요청이 있으면 주요 단품의 풀문 세트 안에서 해당 신규 GIF만 처리합니다.
  • 카민스는 단품3에 등록 후 OFF 상태로 둡니다. 재입고 및 별도 라이브 요청이 있어야 켭니다.
  • 앤드리는 신규 소재만 테스트 중입니다. 이번에 추가 요청된 새 GIF만 대상으로 잡습니다.

광고명과 추적 설정

  • 광고명은 ASC1. {원본 파일명(확장자 제외)}_{CONTENT}입니다. 파일명에 있는 자동화와 (gif)는 유지합니다.
  • UTM은 source=meta, medium=conversion, campaign=메타_{SKU명}을 기존 광고와 대조합니다. CONTENT는 메타_{구분}_{실제라이브일 YYMMDD}_{SKU약어}_{연번}입니다. 캠페인 2는 히든2로 표기하고 연번은 등록 전 실제 광고에서 중복 확인합니다.
  • 예시 메타_히든2_261120_포히_{연번} · 메타_테스트_261123_버칸_{연번}. 카민스처럼 라이브가 미정인 추가분은 기존 작업용 UTM 적용 여부를 확인합니다.
  • 기존 동일 상품의 일반·히든 랜딩을 사용합니다. UTM은 최종 랜딩 URL에 한 번씩만 넣고, URL 매개변수 칸에는 UTM을 중복 입력하지 않습니다. 사이트링크·상품 표시·사이트 요약·영상 보정 등 개선 옵션은 OFF입니다.

등록 후 요청 스레드에 남길 내용

수신 건수 / 신규 등록 / 중복 제외 / 보류를 구분합니다. 신규 건별로 광고명, 세트, 라이브 시각(KST), ON/OFF, 최종 URL·UTM을 Meta에서 재조회하고 MKM에 남깁니다. 완료 회신에는 품목별 건수와 보류 사유를 적습니다.
